# 竞序 · 大学生备赛助手 MVP

首页 Part 01 是简洁的单线时间轴，按往年报名月份排序，展示北京时间当前月份起共 12 个月，只显示参考月份和可点击的竞赛名称。月份属于备赛规划参考，不是下一届确定日程；校内报名因校而异，“挑战杯”两项主体赛按交替年份展示。侧边栏保留全部 15 项竞赛入口（7 项原始赛事 + 8 项扩展赛事），不包含统计建模。

时间轴下方只填写专业、年级、能力，所有竞赛共用。点击竞赛名称进入独立子页，每项竞赛均有画像摘要、系统建议的训练安排、对应资料架、不同的训练模板、DeepSeek 对话与个性化计划接口、工时校验、任务勾选及 Markdown 导出。暂无 API Key 时可使用“先体验模板”。子页“修改画像”返回首页。

训练日期默认由系统建议，可分别设置开始日期和结束日期（含首尾日期，1—84天），自动划分训练周；不足一周按天数折算预算，每周小时数也可修改。调整计划时可同时修改开始、结束日期，必须能够容纳全部未完成任务，否则提示延长日期或增加预算，原计划保持不变。已完成任务及成果记录保留，应用调整前自动归档原版。未指定周期时，后端优先使用未来已公布的准确报名开启日期，否则按照时间轴参考报名月份和届次周期安排。距离较远先生成近期12周；已进入参考月份则安排月内训练。每周投入按距离给出6/8/10小时建议，不代表用户承诺的可用时间。生成的日期属于个人训练安排，不是推定的官方截止日。

## 启动

需要 Python 3.10+。在项目目录执行：

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 编辑 .env，填写 DEEPSEEK_API_KEY；不要把密钥放入网页或提交到 Git。
./.venv/Scripts/python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 http://127.0.0.1:8000 。也可执行 `./start.ps1`。

`.env` 配置：

```dotenv
DEEPSEEK_API_KEY=你自己的密钥
DEEPSEEK_MODEL=deepseek-chat
```

密钥从 https://platform.deepseek.com/ 获取，只写在 `.env` 里；仓库和交付包都不含密钥，`.env.example` 是模板。模型名以自己的账户与官方文档为准：https://api-docs.deepseek.com/ 。修改后重启后端。

**不要使用推理模型（如 `deepseek-flash`）**：思维链会占满输出额度，12 周计划的 JSON 会被截断，生成计划约三次失败两次。后端已会识别截断并自动重试一次，但换成 `deepseek-chat` 才是根治，且耗时从约 39 秒降到约 12 秒。

没有密钥仍可浏览资料、生成明确标注的通用模板，但 AI 对话和个性化计划会提示未配置，不会伪装成模型回复。

## 技术与目录

- `backend/main.py`：FastAPI 后端，使用 HTTPX 调用 DeepSeek；密钥只在后端读取。
- `backend/catalog.py`：7 项原始竞赛资料、带年份和来源的节点、资源与差异化训练模板。
- `backend/catalog_expansion.py`：另外 8 项扩展竞赛；训练主题由赛项自动生成，粒度比原始 7 项粗。
- `backend/scheduling.py`：北京时间、官方日期优先、参考月份回退、近期训练周期及投入建议。
- `frontend/home.html` / `home.js`：首页单线时间轴与共享画像表单。
- `frontend/timeline.js`：以北京时间当前月份起共 12 个月排列参考报名月份，同月只展示一次；按参考周期区分两项“挑战杯”主体赛。投影月份只用于规划，不写入官方赛程。
- `frontend/profile-store.js`：共享画像读写和旧版画像迁移。
- `/competitions/{contest_id}`：独立竞赛备赛页面，直接访问或刷新均可。
- `frontend/`：原生 HTML / CSS / JavaScript，无需 Node.js 或外部 CDN。前后端通过 JSON API 通信，后续可独立替换成 React。
- `GET /api/contests`：全部 15 项竞赛和带来源的时间节点。
- `GET /api/bootstrap?contest_id=innovation`：指定竞赛的配置状态、资料和资源；默认 `cumcm`。
- `POST /api/chat`：请求包含 `contest_id`、`profile` 和 `messages`，只注入当前竞赛上下文。
- `POST /api/plan?mode=ai|template&contest_id=innovation`：请求仅需 `major`、`grade`、`skills`。返回的 `schedule` 包含自动计算的周期、建议工时、日期及依据；旧版传入的时间字段不会控制新计划。
- `tests/test_preparation.py`：自动排期、计划约束和模拟 DeepSeek 的集成测试。

画像统一保存在当前浏览器 localStorage 的 `jingxu-profile-v1`，每个竞赛共用；计划与勾选进度仍按竞赛 ID 独立保存。旧版画像会迁移，原计划不会删除。修改画像不会自动重写已生成计划，后续生成和对话使用最新保存的画像。对话保存在当前浏览器 localStorage 中，刷新后可恢复，换浏览器不会同步。重新生成前会确认替换，导出可备份。AI 接口会发送档案、近期对话，调整建议还会发送当前计划与完成情况；调整建议不会自动覆写计划。

## 数据范围与限制

- 资料核验日期：2026-10-09；子页时间节点附来源链接、年份和精度。首页使用独立的 `registration_reference` 字段展示往年报名月份，子页展示参考依据；不显示初赛、复赛、决赛或通知发布日期。
- “挑战杯”学术科技主体赛当前只有 2025 年参考节点，2026 年不套用专项赛日期；创业计划主体赛部分日程仍待核实。
- 电子设计竞赛明确标注山东赛区示例与模拟电子专题赛报到，不能当作全国所有赛项统一日程。蓝桥杯区分软件科目，并标注组委会通知的拟定日期。
- 报名月份不是固定规则。例如创新大赛2025年系统5月开放，2026年调整至8月；首页显示5—8月参考区间。校内报名引用高校往年样例，不代表全国统一月份。所有数据人工维护，非实时日历。
- Bilibili 链接是搜索入口，知网是文献入口，不是经过筛选的具体课程或论文。**本版没有自动爬虫，也没有定时采集或实时文献检索**；`/api/resources/search` 是实时调用必应公开 RSS 的即时搜索，结果未经核验。
- 模板按竞赛方向及系统排期安排，个性化适配分析由 DeepSeek 完成；暂不进行多竞赛智能排名或组队匹配。短周期模板只适合精简训练，不承诺完成正式参赛全部要求。
- 这是本地单用户原型，没有账号、数据库、限流或生产环境鉴权。若部署公网，需先增加身份验证、调用配额和服务端持久化。

## 关于学习资源搜索

`/api/resources/search` 调用的是必应公开 RSS，有两个已知限制，**搜不到结果通常不是程序坏了**：

- 该接口会限流。被限流时它不返回空，而是返回一整套与关键词无关的结果（实测搜“数学建模”返回过 10 条英雄联盟攻略，搜“算法”返回过 10 条 Windows 帮助页）。后端按关键词重叠度拦掉这类结果，所以页面显示“返回的结果与关键词无关，已全部过滤”，并给出外部搜索入口。
- 结果经过排序：教育与政府域名、MOOC、B站、知网、官方文档优先，万能内容站降权，同一站点最多 2 条。成功结果缓存 10 分钟。

结果一律未经人工核验。若要稳定可用，需改接正式搜索 API，或把该功能降级为纯外部搜索入口。

## 每周成果验收

验收以整周为单位。生成计划后，选择 W01、W02 等周次，一次提交该周全部训练成果。12周计划只有12个周次选项，不再按任务逐条提交。
“本周待办”和完整计划提供整周验收入口，页面汇总该周所有任务与验收标准。

`POST /api/weeks/review` 接收 `week_index`、完整计划、画像、完成状态、成果文本和每周预算。模型给出整周结论与证据，后端检查反馈是否覆盖本周全部任务、引用是否来自提交原文。
AI只评价提交文本，不访问链接或执行代码，不代表官方成绩。

- 通过：应用后统一完成本周全部任务，进入下一待完成周，保留其他周的安排。
- 需要修改：应用后把改进重点写入本周计划，在原有预算内补充成果，再次提交整周验收；不新增零散待验收任务。
- 证据不足：说明本周需补交什么，计划保持不变。

所有调整点击“应用本周反馈”后生效；计划、画像或预算变化后旧预览失效。
自我勾选完成的周仍可做AI验收。旧任务草稿会汇总到对应周，旧评价记录继续保留。
草稿与最近50条评价保存在当前浏览器，按竞赛独立保存，支持导出。重新生成先预览，应用后旧计划与成果自动进入历史版本，不删除旧记录。

评价输出容错：引文只容许空白与兼容字符差异，保存时还原为实际提交原文；改写或编造的引文不作为证据。
模型漏评任务、返回无效结构或引文不匹配时，会收到具体校验原因并自动纠正一次，两次生成共用120秒总时限。
若仍不完整，保存成果和可核对的部分反馈，显示“AI评价未完成”，不判定学生通过或不通过，也不生成计划调整。

## 手动设置备赛日期

“我的备赛计划”可分别设置开始日期、结束日期（含首尾日期，1—84天）和每周时间（1—40小时）。
修改日期后点击“生成计划”或“使用模板”；新计划先预览，应用时归档当前版本及成果，可在历史版本中恢复。
修改输入框本身不会改变现有计划；等待生成时修改日期或预算会使返回的预览失效，需重新生成。
“调整未完成任务”可同时设置开始、结束日期；按容量保存全部未完成任务，不足一周按天数折算预算。
若日期范围无法容纳现有工作，接口会提示延长结束日期或增加预算，不会删任务或覆盖原计划。
这些日期属于个人训练安排，不代表赛事截止时间。旧版 `training_weeks` 仅保留接口兼容，不再作为网页输入项。

## 跨竞赛成长记忆

首页和竞赛页新增“我的成长记录”。每天选择竞赛、日期，记录计划用时、实际用时、完成情况、目标、成果与卡点；练习标签可选。
同一竞赛同一天保存会更新原记录，支持修改、删除与JSON导出。记录在当前浏览器的 `jingxu-growth-v1` 中跨竞赛共享，重新生成计划不会清除。
最近30条可在页面查看，完整记录可导出，最多保留500条且到达上限时提示用户自行清理，不自动删除。

生成计划时可关闭“参考跨竞赛成长记录”。开启后将最近最多120条记录发往后端，按最近28天统计；摘要及近期8条提供给AI，不能据此推定已经掌握能力。
- 至少有一个完整7天窗口（包括明确记录的休息日），才按完整窗口平均实际投入调整工时。
- 没有完整窗口，不把漏记日期当作没训练，不外推每周工时。零散成果与卡点仅供AI安排内容参考。
- 完成情况以自报“完成=1、部分=0.5、卡住=0”计算参考指数，不等于验收通过率。低于0.5时，在观察工时基础上留20%缓冲。
- 建议工时不会超过用户当前预算，按半小时向下取整，最小1小时。若实际投入不足1小时，会明确提示最低计划可能仍不可行。
- AI计划参考通用练习与反复卡点，保留新竞赛专项要求；模板仅调整工时，仍明确标为通用模板。

`POST /api/growth/summary` 不调用模型，可预览调整依据。`/api/plan` 新增可选 `growth_logs`，省略或传空列表保持原行为。
计划展示实际引用的竞赛、记录天数和预算变化。跨竞赛记忆以本地单用户为范围，不会跨浏览器或设备同步；使用同一浏览器的其他人也共享这些记录。

## 网页备赛日历

首页“我的备赛日历”汇总当前浏览器已保存的竞赛计划，可按竞赛筛选；竞赛工作台的“备赛日历”只显示该竞赛。
月历支持前后月份、回到今天、跳到计划开始，点击日期查看训练周概括、周工时、任务完成数和本周改进重点。
日期格上的训练周覆盖完整起止日期；每日成长记录以标记提示，点击可查看实际投入与成果。
生成、调整计划或勾选任务后日历同步更新，跨标签页保存也会同步。该日历是个人周训练安排，不推定官方赛程或每日任务分配。

## 导航与参赛列表

左侧统一为“竞赛 / 备赛 / 成长”。备赛下包含“总日历”和“正在参加比赛”，后者按已参加的竞赛显示子目录；成长下包含“我的画像 / 每日记录 / 成长总结”。
竞赛、总日历、画像、记录、总结在主内容区分别展示，不再把所有面板堆在一页。

点击“参加比赛”才加入参赛子目录；收藏与参赛分别保存。旧画像、计划、验收及成长记录不变，不自动将旧计划或收藏视为已参加。
可从正在参加列表移出比赛，已有资料和训练记录保留。参赛列表保存在 `jingxu-library-v1.participating`，保留原收藏字段及其他设置。
总日历只汇总正在参加的比赛；单项比赛仍可查看原有独立计划与日历。

比赛内顶部标签为“计划 / 日历 / 每周验收 / 资料”，每日记录提供快捷入口。AI教练通过按钮展开，可关闭或按Escape收起。
保留原有 `/#profile`、`/#growth-memory`、`/#plan-calendar` 和比赛内的锚点入口，支持刷新与浏览器前后退。

## GitHub Desktop 协作与线上部署

GitHub 仓库 Settings → Collaborators → Add people 邀请队友。每个人使用自己的账号，在自己的功能分支提交，通过 Pull Request 合并 main。
本机 .env 不会随 Clone 获取；队友复制 .env.example 为 .env，私下配置自己的有效密钥。

Render 部署方式一：New → Blueprint → 选择 GitHub 仓库，读取根目录 render.yaml，按提示填写 DEEPSEEK_API_KEY。
部署方式二：New → Web Service → 选择同一仓库，Runtime Python 3，Branch main，Root Directory 留空；
Build Command 为 pip install -r requirements.txt，Start Command 为 uvicorn backend.main:app --host 0.0.0.0 --port $PORT。
Environment 中设置 DEEPSEEK_API_KEY 和 DEEPSEEK_MODEL=deepseek-chat。
.python-version 指定 Python 3.12，requirements-lock.txt 固定本次已验证的依赖版本。
仓库根目录应直接包含 backend、frontend、requirements.txt、render.yaml。

GitHub Pages 仅提供静态托管，无法单独运行本项目的 Python 后端。
代码合并到 main 后，Render 可自动重新部署。免费 Web Service 空闲后会休眠，首次访问可能需要等待唤醒；正式路演前预留启动检查时间。
部署链接在创建服务后由 Render 提供；添加配置文件本身不会发布网站。

当前服务没有登录或调用配额，公开地址上的访问者可调用后台付费模型。团队演示阶段应控制分享范围，公开开放前补访问控制与调用限制；私有 GitHub 仓库不意味着网站也私有。
用户计划、每日记录等仍保存在各自浏览器。线上域名与 localhost 的存储独立：上线前从本机的“成长总结 → 统一备份与恢复”导出，再到线上网站导入。
多人共同修改代码不等于多人共享同一份用户训练数据。此版本尚未提供账号与服务端数据同步。

## 日期范围接口

- `POST /api/plan` 接收 `start_date` 和 `end_date`（ISO 日期，必须成对传入），并沿用 `weekly_hours`。开始日期不得早于北京时间今天，最多84天；同一天表示一天训练。
- `POST /api/plan/adjust` 接收 `start` 和 `end`，最多64周（含保留历史记录后训练周总数不超过64）。不足一周的容量按天数折算；不会缩减未完成任务工时或排到结束日期之外。
- 为兼容旧客户端，未提供日期时仍支持原有系统建议/`training_weeks`；调整请求未提供 `end` 时保留旧版按剩余工时推算结束日的行为。日期与 `training_weeks` 不可同时设置。
- 本地旧计划和历史版本无需删除；日期设置将从已保存计划恢复，新的日期设置也会进入统一备份。
